# Deploy Jivan to Cloudflare Pages

Jivan is exported as a static site. It does not require a database, a Next.js server, or a Workers runtime.

## Cloudflare Pages settings

- **Production branch:** `main` (merge a reviewed pull request into `main` to publish)
- **Build command:** `npm run build`
- **Build output directory:** `out`
- **Node.js:** 22
- **Root directory:** `/`

Set `NEXT_PUBLIC_SITE_URL` to `https://jivanrx.online` for canonical URLs and metadata. The code uses that value as its default. `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` is optional (see `SEO-INDEXING.md`).

The build prepares the medicine slug manifest, redirects and `robots.txt`, generates the sitemap index (`/sitemap.xml` → `/sitemaps/*.xml`), exports the pages, and validates the static output. A successful build checks that every sitemap URL resolves to generated HTML with a matching canonical URL, no `noindex` directive, the expected hreflang policy, a title, a description and exactly one H1, and that non-indexable locales render `noindex`. The URL count is derived from the content inventory (currently 561 English URLs).

## Deploy from a local checkout

```sh
npm ci
npm run build
npx wrangler pages deploy out --project-name jivan-medicine --branch main
```

For a preview, replace `main` with the branch name. Do not deploy the `out` directory until `npm run build` finishes successfully.

## Notes

- Next.js static export is configured in `next.config.ts`; the deployment output is `out/`.
- `public/_headers`, `public/_redirects`, and `public/robots.txt` are deployed as static Cloudflare Pages configuration files. `_redirects` and `robots.txt` are generated by `npm run prepare:static`. The `www` → apex 301 is a Cloudflare Redirect Rule (see `SEO-INDEXING.md`).
- Search indexing setup and troubleshooting (Search Console, sitemap submission, Cloudflare bot settings) is documented in `SEO-INDEXING.md`.
- The site performs optional client-side public-source lookups for unmatched searches (RxNorm, openFDA, and Wikipedia). Search terms are sent directly to those services; no API key, database, or server-side proxy is used.
- Never put private API keys or credentials in `NEXT_PUBLIC_*` variables or in the static bundle.
